# PaperSearch 路线图

更新：2026-11-10。接下来有两条主线：**让批量下载和安装更省心**，以及**在 PDF 之外交付可以直接阅读和分析的全文**。项目能做什么见 [README](../README.md)，怎么运转见 [架构说明](./ARCHITECTURE.zh.md)。

想要的功能、遇到的问题，欢迎在 Issues 里提。

## 已完成，随下一个版本发布

- **开放下载和机构下载同时进行**：批量下载时，开放下载（开放获取、出版社 API 等不用浏览器的渠道）查到第一篇拿不到的，浏览器立即开始下这篇，开放下载接着查后面的；浏览器一次仍只下一篇。学校登录在开始后几秒就提示，不用等开放渠道全部查完；进度窗口顶部和底部的数字都按整批算，当前论文下面一行写开放下载和机构下载各下到多少篇（如“开放下载 15 篇 · 机构下载 9 篇”），相加就是底部的“成功”；结束卡片也按这两类汇总，出版社 API、Sci-Hub、预印本写在开放下载后面的括号里。
- **点数字看是哪些文章**：进度窗口底部的“成功”“失败”“剩余”可以点开。成功的按开放下载、机构下载分组，点一篇打开它所在的文件夹并选中 PDF；失败的按原因分组，点一篇在浏览器里打开文章页，方便手动下载；剩余的分正在下载、排队等机构下载、开放下载还没查。各组可以同时展开，列表最高半个屏幕，篇数多时在里面滚动；下载中和整批结束后都能看。
- **系统通知可以测试**：设置里打开“需要处理时发系统通知”时，会检查系统是否允许 PaperSearch 弹出通知；开关下可以发一条测试通知，系统没允许或没看到通知时，告诉你去哪里改，并能直接打开系统的通知设置。设置等卡片的背景不再透出后面的内容。
- **进度胶囊拖动跟手**：Mac 上拖动胶囊由系统直接跟随鼠标，机器忙时也不落后，拖到屏幕底边能贴住；卡片放在靠下的位置收起时，胶囊留在卡片下沿，不再跳到上面。旧的进度窗口已删除，只保留胶囊。
- **学校订阅下载等待更合理**：出版社的安全验证和程序自己选学校的时间，不再占用学校登录页的等待时间；点 PDF 后遇到验证、PDF 被当成下载文件时，不再一直等到超时，PDF 照常保存并核验；一步的时间恰好用完时，不再把已拿到的 PDF 丢掉、也不再当成浏览器卡死；PDF 首页认不出 DOI 和题名时（如 Science），拿到就保存、交给 PaperSearch 核验，不再多花约一分钟找别的版本。
- **诊断记录跟着论文放**：下载出问题的篇目，诊断记录和截图放进该篇文件夹里的 `diagnostics/`，文件名开头和 PDF 一样；下载顺利的和开放渠道直接下到的文章没有这个文件夹，记录留在这次运行的 `runs/` 里；整批运行记录在下载文件夹的 `runs/`。
- **设置窗口**：装了学校订阅下载的电脑上，`paper-search settings` 或胶囊齿轮打开；下载文件夹、等待和提醒、API key 分三页，每个 key 填好可以点“测试”；胶囊可切换中文/English；装好扩展后自动打开。终端里的 `paper-search setup` 照常可用。
- **测试 API key**：`paper-search config test` 在终端检查已填的 key 能不能用。
- **引文和参考文献更全**：施引文献改用 OpenAlex，不再只取 100 条；参考文献按出版商清单的原顺序编号，并标出缺了哪几号。
- **学校订阅下载装得更小**：PDF 组件换成更轻的 pypdfium2，去掉用不到的附带组件，依赖从约 490 MB 降到约 210 MB；下载缓存装完就清掉；没有图形界面的服务器上不再安装它。
- **升级后扩展自动更新**：升级 PaperSearch 后第一次用到学校订阅下载时，先自动更新扩展再下载，不用再手动运行 `paper-search carsi update`；不想自动更新可以关掉。
- **下载更准**：Science 这类文章页不写题名的网站，用论文元数据里的题名核对 PDF；文件名和结果里的期刊名、题名不再出现 `&amp;`、`<i>`。

## 进行中：批量下载和安装更省心

| 目标 | 你会得到什么 |
|---|---|
| 一次下几百篇不中断 | 长批次、跨出版社的下载更稳；浏览器卡住或崩溃只影响当前这一篇，已下好的文件不丢 |
| 登录和验证更顺 | 覆盖更多学校登录和验证页面；登录过期时及时提示你重新登录，而不是一直等 |
| 新电脑一次装好 | 从安装、浏览器准备、选学校到下好第一篇，每一步都有提示；Windows 的升级和旧配置迁移更顺 |
| 进度胶囊更好用 | 提醒时机更准，学校登录页能自动放行时不提前打扰；减少 Windows 上浏览器启动、换页时短暂跳到前台；显示效果更清楚 |
| 失败原因说清楚 | 分清没权限、网站限制、验证没完成、网络问题和程序错误，并说明哪些可以重试、重试前要做什么 |
| 正文和补充材料分开汇报 | 每篇论文的正文、补充材料各拿到了多少，一眼看清是否完整 |

## 计划中：全文包

除了 PDF，再交付一份可以直接阅读和分析的全文：

- **原始全文**：开放来源和出版社接口提供的 XML（JATS 等），以及机构下载时的全文网页；先核对 DOI 和题名，摘要页、受限页不算全文。
- **Markdown 阅读副本**：章节、正文、图注、引用、表格和公式都转过来，原始文件一并保留，方便交给 AI 阅读和引用。
- **正文图片**：尽量保存原图，图号、图注和正文里的引用一一对应。
- **更完整的补充材料**：覆盖更多网站和旧式页面，每个附件逐项列出。

先从 PubMed Central / Europe PMC 和已有的 Springer Nature 全文接口做起，再扩展到其他出版社的 XML 和机构下载的全文网页。

## 计划中：检索论文、搜正文片段再优化

先看同类工具在检索论文和搜正文片段上是怎么做的，再定改进方向，目标是找得更全、更准，结果更容易核对。

## 候选方向（欢迎投票）

- **Zotero 整合**：找出文献库里缺 PDF 的条目，下载后挂回对应条目，并对文献集和附件去重。
- **更多学校访问方式**：除了 CARSI，评估 WebVPN、EZProxy 等学校提供的访问方式。
- **其他国家的学校登录**：除了中国的 CARSI，支持经 eduGAIN 互联的其他国家学术身份联盟（如美国 InCommon、英国 UK federation），用本校账号下载订阅论文；每个联盟需要当地用户协助实测。
- **并行下载**：批量下载时同时处理多篇，缩短几十上百篇的总耗时。开放渠道和机构下载已经同时进行（见上）；接下来是机构下载按出版社分开，在遵守每家下载上限、不让学校的访问被出版社暂停的前提下评估多篇并行的方式。

## 长期维护

- 请求限流、缓存和重试做得更统一，减少接入新来源时的重复配置。
- 命令、JSON 输出、随包 Skill 和文档始终保持一致；新功能都配自动化测试和真实下载验证。

## 参与

- **下载失败**：使用下载失败 Issue 模板；支持导出的源码版本可附上核对过的记录包，已安装版本没有此命令时先提供版本、系统、DOI 和现象。
- **想支持某家出版社**：说明网站和一篇你有权限的文章 DOI；也可以按 [carsi/CONTRIBUTING.md](../carsi/CONTRIBUTING.md) 自己加规则。
